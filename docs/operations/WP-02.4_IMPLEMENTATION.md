# WP-02.4 bounded writer implementation

Relates to #3 and #34; draft PR #190. Dependency #31 merged in PR #177;
I-18 prerequisite #167 is present. This adds code to the existing WP-02.4 branch.
It does not claim WP-02.4 acceptance or start #35 / #43.

## Scope and integration decision

The original preflight identified missing acquisition build wiring. Following the
user's explicit request to proceed with implementation, this draft proposes the
smallest wiring change: the existing Android `:app` compiles acquisition main/test
source directories. It adds no module, plugin version, architecture or contract.
There is no new owner comment approving this choice; review is still required.
The historical preflight remains available without presenting its facts as the
current tree.

The writer adapts S1's bounded chunk / fsync / atomic rename / hash / ZIP approach
into the approved acquisition destination. It uses explicit I-18 v1 metadata,
ordered `size_bytes` entries and a manifest published only after chunk completion.
A single worker serializes I/O and a fixed-delay timer performs periodic fsync.
Producer calls block instead of using an unbounded queue. Record/session/storage
limits reject further writes and prevent a later `COMPLETE` claim.

Manual recovery preserves context and original chunk bytes, counts only valid
records, refuses legacy metadata inference and keeps abandoned evidence diagnostic.
Export validates the selected complete session's declared paths, sizes and hashes
before writing and checks bytes again during ZIP copying. Unrelated files never
enter the ZIP. Any export exception requires the caller to discard partial output.

See `android/acquisition/README.md` for the API preconditions. Producer payload
schema validation and supplying real metadata remain caller responsibilities.
The app has no live acquisition or document-picker caller, so this draft does not
claim working sensor recording, UI export, force-stop restart or field validation.
Power-loss directory durability and on-device behavior remain pending.
