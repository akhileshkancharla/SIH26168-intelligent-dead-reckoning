# WP-02.3 LocationManager contract adapter

Relates to #3 and #33. C-01 snapshots LocationManager callbacks into the existing I-02 LocationGnssFix schema and common evidence envelope. The imported S1 artifact remains unchanged.

The adapter preserves provider, mock flag, elapsed-realtime source/arrival clocks, coordinates, available accuracy/altitude/speed/bearing values and auxiliary wall time. Wall time never replaces the scientific epoch. Presence flags produce explicit nulls and a matching field mask; valid zero measurements remain present. It never relabels network/fused providers as GPS, fabricates accuracy, clears mock provenance, or treats a returning observation as an accepted navigation fix. C-09 and C-07 own those decisions.

A session-scoped adapter encodes null providers as `location:null` and non-null providers as `location:provider:<length>:<original-value>`. Sequence and timestamp maps use that exact serialized stream key, so a missing provider cannot alias a literal provider named `<missing>` (or `null`). Original nullable provider values remain untouched in raw evidence. The adapter assigns per-provider sequences and unique evidence IDs, records immutable snapshots first, and forwards schema-valid observations through shared LIVE_DEVICE ingress. Duplicate/backward timestamps, missing required accuracy/provider, non-finite values, and schema-range violations remain diagnostic evidence with typed invalid gates and original values; they do not reach runtime. Invalid diagnostics require the recorder's diagnostic path, rather than serialization as accepted I-02. A recorder failure propagates and blocks runtime publication; the session owner must stop and mark incomplete/degraded evidence. Reentrant publication fails explicitly. Construct a new adapter after session or boot changes.

The session owner supplies durable LocationEvidenceRecorder and live ingress, registers ContractLocationListener in the user-started location foreground-service lifecycle, handles permission/registration failures, and records provider-state and legacy status callbacks (the listener copies the legacy extras Bundle). This deliverable does not wire the replay launcher to live acquisition, alter GNSS status/raw-measurement capture, or replace the C-02 writer. Optional fields use minSdk 26 APIs; mock provenance uses the appropriate pre/post Android 31 API.

Run Gradle 8.10.2 with `gradle -p android testDebugUnitTest lintDebug`; run `python ci/generate_contract_bindings.py --check` and `python ci/verify_repository.py all`. Synthetic regressions cover optional absence/zero, immutable payloads, identity and source-time preservation, provider/mock provenance, independent streams, duplicate/backward times, invalid measurements, and recorder failure. Exact verification outcomes are recorded in the PR. No physical accuracy, rates, outage/reacquisition performance, battery/thermal result, S1 completion, or scientific validation is claimed.

Attribution: callback extraction follows the imported S1 RecordingService and existing authoritative I-02/envelope schemas. Adaptation and tests prepared with Codex assistance.
